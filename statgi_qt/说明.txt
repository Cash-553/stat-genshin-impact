StatGI · Qt 版（新界面）
================================

这是重写的新界面。旧的 Tk 界面还在根目录，暂时两版并存，
等这个版本成熟了就把 Tk 那套删掉（见文末「以后的收尾」）。

怎么跑
------
在命令行里：

    cd E:\收益识别\statgi_qt
    python main.py

（根目录那套识别/统计模块会被自动引用，不用复制过来。）

文件说明
--------
  main.py         入口。双击/命令行跑这个
  qt_window.py    主窗口：无边框 + 圆角 + 背景图 + 玻璃卡片 + 侧边栏
                  托盘、热键、统计条窗口、退出确认也在这儿
  qt_pages.py     五个页面：启动 / 今日统计 / 收益统计条 / 收益记录 / 设置
  qt_widgets.py   通用控件：卡片、设置行、开关、折叠区
  qt_theme.py     配色与样式表（颜色直接读根目录的 theme.py，
                  也就是你在「设置 → 外观」里选的背景色 / 强调色）
  qt_core.py      数据与监测核心（AppState）：统计、开始/停止监测、唯一定时器
  qt_bar.py       收益统计条窗口（OBS 用的那个小窗口）
  qt_dialogs.py   图标管理、区域框选
  qt_tray.py      系统托盘 + 全局热键

  预览_*.png      各页的样子

怎么打包
--------
用根目录的 StatGI_qt.spec（跟 Tk 版的 StatGI.spec 是两份，互不影响）：

    cd E:\收益识别
    python -m PyInstaller StatGI_qt.spec --noconfirm

打出来的在 dist\StatGI\，再复制到发布版文件夹，写好干净的
config/settings.json、清掉 data\，最后压成 zip。

打包入口是根目录的 **app_qt.py**（不是 statgi_qt/main.py）——
PyInstaller 要能分析到 qt_window / qt_pages 这些在子目录里的模块，
app_qt.py 会把 statgi_qt 加进搜索路径，spec 的 pathex 也带了 'statgi_qt'。
不加的话打出来的 exe 一启动就 ImportError。

V0.8 打包结果（2026-09-19）：
    文件夹 332.7 MB / 443 个文件      zip 143.2 MB
    实测：启动 20 秒仍存活、内存约 178 MB、没有 error.log

体积说明：比 Tk 版（249 MB）多出来的主要是 Qt 的 DLL
（Qt6Core / Qt6Gui / opengl32sw 等）。已经排掉了用不到的 Qt 模块
（WebEngine / QML / 3D / 多媒体…），tcl/tk 也排掉了。

⚠ QtOpenGL / QtSvg / QtXml / QtPrintSupport 这几个**不能排** ——
QtWidgets 内部可能会用到，排掉的话打包版一启动就崩，
报错还是很难懂的「plugin not found」。省那几 MB 不值得。

errlog 对 Qt 版也生效
---------------------
errlog.install_hooks() 里除了 Tk 那个钩子，还装了 Qt 的 QMessageHandler。
为什么需要：Python 异常如果发生在 Qt 的槽函数里，不一定走 sys.excepthook，
而打包成窗口版后 stderr 是被丢掉的 —— 不钩的话等于什么都没记到，
出了问题只能看到「程序闪退了」。QMessageHandler 是 Qt 唯一的出口。

检测更新（坑不少，记下来）
--------------------------
仓库改过两次名，地址一定别写错：

    genshin-income-tracker   最早的旧名，**已经不存在了**
                             （Tk 版就错在这儿，永远显示「检测失败」）
    StatGI                   别名，会 301 重定向到下面那个
    stat-genshin-impact      现在的真名  ← 用这个

另外**不能用 `!=` 比较版本**：

  GitHub 上最新发布是 v0.7、而本地已经跑到 v0.8 时，`latest != current`
  会成立，于是弹「发现新版本 0.7」—— 把**老版本**当新版本。
  字符串比较下 "0.10" < "0.9"，也是错的。

所以用 is_newer_version()（按数字段比较）：
    0.7  vs 0.8   -> False（已是最新）
    0.9  vs 0.8   -> True
    0.10 vs 0.9   -> True
    0.8  vs 0.8   -> False

刷新机制（重要，专门为"不拖影"设计的）
--------------------------------------
全程序**只有一个定时器**（200ms，在 qt_core.AppState 里），它每轮只做三件事：

  1. 排空识别线程的结果队列
  2. 检查有没有跨过换日时间
  3. **比较数据有没有变 —— 没变就一个信号都不发，界面完全不动**

数据真变了才发 stats_changed，各页面收到后自己去比"哪个数字不一样"，
只改那一个标签。实测（都过了）：

  · 改一个材料数量：行控件和数量标签**还是同一个对象**（没重建），控件总数不变
  · 静置 1.5 秒（定时器跑 7 次）：stats_changed 发了 **0 次**
  · 增/删材料：只动那几行，其它行不动
  · 切到别的页时改数据：材料页控件数**不变**（不可见就不刷，等显示出来再补）

绝对不做的事：为一个数字重绘整个窗口、删光控件再重建、多个定时器重复刷。

注意：收益统计条自己有一个 500ms 定时器，但它**只刷那一个小窗口**，
跟主界面互不影响（主界面切页、拖透明度都不会牵动它）。

为什么文件都叫 qt_ 开头
-----------------------
因为根目录的 Tk 版已经有 ui_pages.py / ui_widgets.py 这些同名文件。
Python 的 import 是按名字找的，撞名会加载错（已经踩过一次坑）。
等 Tk 删掉之后，这些 qt_ 前缀就可以去掉了。

跟 Tk 版不一样的地方（有意为之）
--------------------------------
  · 用 Qt 自带托盘和对话框，不再依赖 pystray、不用自己画标题条
  · 全局热键改成轮询（120ms 一次），不再子类化窗口过程
    —— Tk 版在子类化窗口过程上踩过坑（吞掉消息导致最小化失灵）
  · 图标管理 / 退出确认用的是系统标题栏，不再自绘
  · 检测更新的结果用 Qt 信号从后台线程发回主线程
    （后台线程绝对不能直接碰控件）
  · 开关是自己画的（胶囊轨道 + 白色圆点 + 120ms 滑动动画）
    —— QSS 画不出圆点，用 QCheckBox 穿皮肤的话就是一个色块，分不清开关
  · 默认背景是**纯色**（跟着设置里的「背景颜色」走），不自己造渐变图
  · 换背景色 / 强调色**立即生效**，不用重启

⚠ 键名对齐：两处千万别写错
--------------------------
1) 开发者选项那个开关必须写 dataset_enabled（不是 dataset_collect）
   —— DatasetCollector 只认前者。

2) 画面变化灵敏度必须写 change_threshold（不是 change_level）
   —— 识别核心读的是 change_threshold。Tk 版在这儿有个 bug：
     下拉框按 change_level 显示、保存却只写 change_threshold，
     于是 change_level 永远停在老值，**看到的值和实际用的值对不上**。
     Qt 版按 change_threshold 反推显示，并且两个都写，
     所以显示的就是真在用的。

档位表（两个下拉框共用同一套名字，定义在 config_manager.py）
-----------------------------------------------------------
  文字识别频率 OCR_LEVELS     数值 = 毫秒，越小越频繁
      性能 100 / 标准 150 / 省电 250 / 极致省电 500
      （默认 标准 = 150）

  画面变化灵敏度 CHANGE_LEVELS  数值 = 变化阈值，越小越灵敏
      性能 1.0 / 标准 2.0 / 省电 4.0 / 极致省电 8.0
      （默认 标准 = 2.0）

  名字统一成同一套，用户不用分别记两套叫法。
  老设置里存的数值（比如 250 / 4.0）不在新表里时，
  按"最接近的一档"显示（250 -> 省电，4.0 -> 省电）。

这类 bug 的特征是：界面能点、值也存下去了，**只是存到了一个没人读的键上**。
改设置项时一定要去 detector.py 确认它到底读哪个键。

改完立刻生效是怎么做的
----------------------
识别线程是用 settings 这个 dict 构造 Detector 的，而 Detector 在构造时
把一部分值**复制**成自己的属性，所以光改 settings 它不会变。
AppState.apply_live_settings() 负责把新值推回去：

  要推的：change_threshold / ocr_interval(还要除1000) / _absence_seconds
  不用推：enable_mora / enable_material / enable_artifact /
          only_foreground / auto_register_material
          （这些每次 tick 都现读 self.settings）

颜色为什么要写成 T.XXX
----------------------
qt_theme 里那些颜色是**可变的模块级变量**，别的模块必须写：

    import qt_theme as T
    ... label_qss(T.TEXT, 14) ...

**不能**写 `from qt_theme import TEXT` —— 那是导入时把值复制一份，
之后改颜色它还是老的（这正是"换背景色点了没反应"的原因）。
换颜色时调 qt_theme.reload_colors() + MainWindow.rebuild_ui()，
界面重建一遍就应用上新颜色了。
